# 시간표 경로 탐색과 역 안내 (2026-09-21 Phase)

`POST /v1/journeys/predict`는 이제 열차별 출도착 시각으로 경로를 탐색한 뒤, 해당 경로의 실제 예정 출발시각마다 혼잡도를 추론한다. 인접 구간의 가정 소요시간으로 경로를 고른 뒤 시간표를 덧붙이는 방식은 기본 경로 탐색에서 제거했다. 이는 **2025-09-30 공개 시간표 스냅샷 내 최적화**이며 현재 운행·지연을 반영하는 실시간 경로 안내는 아니다.

웹페이지 수정일과 실제 파일 기준일을 구분한다. 확인일은 2026-09-21이며, 이때 확인한 다운로드 목록의 최신 시간표 파일은 2025-09-30이었다. [별도 시간표 API](https://data.seoul.go.kr/dataList/OA-22750/S/1/datasetView.do)는 인증키가 필요해 현재 데이터 경로에 포함하지 않았다.

- `journey_enrichment/collect.py`: 공식 파일 다운로드 및 바이트 수·SHA256·파일 식별자 기록. 원본은 Git 제외.
- `scripts/prepare_enrichment.py`: UTF-8 BOM/CP949 처리, 부역명·이전 역명 정규화, 역/노선 코드 매핑. 현재 파일명·기준일을 명시적으로 고정하므로 새 파일 수집 후 버전 변경 시 이를 함께 검토해야 한다.
- 시간표 STT는 도착, EDT는 출발이다. 24시 이후 값은 이전 영업일의 연장 운행으로 보존한다. 00:00:00 자리표시자는 결측으로 처리하고, 요일 미상 77,233행과 운영 범위 밖 140,435행은 경로 seed에서 제외한다.
- 요일 DAY/SAT/END는 한국 날짜의 평일/토요일/일요일·공휴일에 연결한다. 원본 전체 파일은 로컬 SQLite `source_files.original_gzip`에 보존했다.
- SQLite `timetable_stops`, `amenities`, `access_doors`는 버전 해시가 달라질 때 seed를 갱신한다. 원본 다운로드가 없는 환경도 저장소의 정규화 seed로 재현된다.

## 경로 알고리즘

`app/scheduled_routing.py`의 시간 확장 그래프 Dijkstra는 플랫폼에서 탑승 가능한 열차와 열차 안에서 이어지는 정차 이벤트를 분리한다.

1. 요청 시각부터 6시간 내 연결만 탐색한다. 이전 영업일의 자정 이후 운행도 포함한다.
2. 같은 운행 식별자의 연속 정차 기록만 연결한다. 지선·급행은 지원 구간 topology와 일치해야 하며, 잘못된 시각이나 누락된 정차를 건너뛰어 가짜 열차를 만들지 않는다.
3. 같은 열차는 다음 역 정차 후 그대로 이어 탈 수 있다. 다른 열차로 변경하면 승강장 이동 여유 1분을 둔 뒤 실제 다음 출발까지 기다린다.
4. 노선 간 환승은 확보한 방향별 공식 보행시간의 평균을 사용하며, 없는 경우 기존의 명시된 5분 가정을 사용한다. 방향별 개별 보행시간/엘리베이터 이용 경로를 최적화하는 것은 아직 아니다.
5. 기본 전략은 가장 이른 도착, 동률이면 적은 탑승 횟수다. `fewest_transfers`는 탑승 횟수를 먼저 최소화하고 도착시각을 비교한다. `allow_express=false`는 급행을 후보에서 제외한다. 출발·도착 호선 제약은 첫·마지막 탑승 호선에 적용한다.
6. 연결 경로가 없으면 422로 이유를 반환한다. 기본 모드에 가정 구간을 몰래 혼합하지 않는다. `use_timetable=false`를 명시하면 기존 가정 소요시간 경로를 사용할 수 있다.

최적이라는 의미는 수집한 노선 연결과 위 보행·승강장 이동 가정, 6시간 탐색 범위 내에서의 최적이다. 역 출입구에서 승강장까지 걷는 시간, 실제 지연, 임시 운휴, 혼잡으로 승차하지 못하는 상황은 포함하지 않는다. 서울교통공사 1~8호선 운영구간과 서울 9호선 범위이며 수도권 타 운영기관 전체가 아니다.

## 칸별 배분과 문 안내

각 실제 탑승 leg에 대해 출발역 접근 문, 도착역 접근 문, 직전 환승 승차 문, 다음 환승 하차 문을 방향 일치 여부로 필터링한다. 이 호차를 중심으로 거리 기반 가우시안 선호 가중치를 만들고, 자료가 있는 그룹끼리 평균한 뒤 전체 호차 평균이 1이 되도록 정규화한다. `scenario_strength`(기본 0.2, 허용 0~0.3)를 혼합하므로 열차 전체 평균 혼잡도는 유지된다.

이는 해당 이동 경로의 이용객이 문 근처 칸을 선호한다는 **조건부 배분 시나리오**다. 실제 승객의 목적지 비율과 칸별 정답이 없어 학습·검증된 칸별 예측으로 해석할 수 없다. 문 번호는 해당 호차의 위치 근거이며 문별 혼잡도는 추정하지 않는다. 데이터가 없으면 그 그룹을 제외하고, 모든 그룹이 없으면 균등 배분한다.

정확한 **출구 번호 → 방향별 최단 호차·문** 매핑은 확보하지 못했다. `exit_mapping_status=unavailable_escalator_access_proxy_only`로 노출하며, 에스컬레이터 인접 문은 출입 접근의 대체 정보로만 사용한다. 종착역 등 진행 방면을 확인할 수 없는 곳에 반대편 문을 대신 표시하지 않는다.

칸별 `prediction_kind`, `car_ground_truth_count=0`, 민감도 범위(신뢰구간 아님)를 유지한다. `location_features`에 실제 사용한 문·환승 경로 근거를 반환한다. 전체 여정 요약은 탑승 시간 가중이며 보행·대기시간을 제외하고, 같은 열차의 정차시간은 탑승 시간에 포함한다.

## API / 화면

- 여정 응답: `timetable`, 열차번호·행선지·출도착 시각, 대기·정차 시간, 환승 `door_guidance`, 출발·도착역 `endpoint_facilities`, 승하차 접근 문.
- `GET /v1/stations/{station_id}/facilities`: 시설 설치 여부와 수유실 위치. 자료 없음(null/상태)을 시설 없음(false)과 구별한다. 실시간 가동 여부는 아니다.
- `GET /v1/stations/{station_id}/timetable?week=DAY&limit=100&offset=0`: 기준일과 원본 행 번호가 포함된 정차 기록. limit 최대 500.
- 화면 문 위치·역 편의시설 상세에 기준일과 자료 한계를 함께 표시한다.

2026-09-21 08:15 예시(공개 시간표를 해당 날짜에 적용):

| 경로 | 선택 | 예정 소요시간 |
|---|---|---|
| 건대입구 → 고속터미널 | 7호선 | 14분 10초 |
| 사당 → 압구정 | 2호선 → 교대 → 3호선 | 21분 |
| 김포공항 → 봉은사 | 9호선 급행 허용 | 43분 40초 |
| 김포공항 → 봉은사 | 일반만 | 65분 35초 |

교대 환승 예시: 하차 10호차 4번 문, 승차 7호차 4번 문. 원본 응답은 `docs/journey-enrichment-example.json`, 비교 기록은 `artifacts/scheduled_route_examples.json`에 저장했다. 이 숫자는 실제 해당일 운행을 검증한 결과가 아니다.

검증은 급행 추월, 환승 놓침, 동일 열차 정차, 단축 운행 후 열차 변경, 심야 영업일, 주말 구분, 최소 환승, 연결 없음, 칸별 평균 보존 및 문·시설 API를 포함한다. 로컬 테스트 실행: `.venv/bin/python -m pytest -q`. UI 검증은 `ENRICHMENT_API_URL`을 새 백엔드 주소로 설정하여 `npm --prefix frontend test -- enrichment.spec.ts`로 실행한다.

## 도착역의 호선 선택 (2026-09-21 보완)

목적지 역에서 요청한 호선까지 걸어서 이동하면 여정을 종료한다. 그 호선 열차를 다시 타고 돌아오도록 요구하지 않는다. 예: 2호선 삼성 → 8호선 잠실은 2호선으로 잠실까지 탑승하고, 마지막 역내 이동 후 **8호선 잠실 도착**, 열차 환승 0회로 표시한다.

마지막 역내 이동은 기존 API 호환을 위해 `kind=transfer`를 유지하되 `purpose=destination_access`, `counts_as_transfer=false`로 구별한다. 보행시간은 소요시간에 포함하고 대기시간은 추가하지 않는다. `to_line`, `arrival_station_id`, `destination_access_minutes`를 반환하며 도착 편의시설은 요청한 호선 기준으로 제공한다. 실제 탑승 leg와 하차 문 안내는 타고 온 열차 호선을 유지한다. 프론트엔드는 마지막 역내 이동을 환승 노드로 표시하지 않고 지정 호선을 도착 노드에 표시한다.
