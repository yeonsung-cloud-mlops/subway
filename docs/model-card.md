# 모델 카드: metro-all-ewma-location-scenario-v2

## 대상과 근거

서울교통공사 1~8호선 운영구간 및 서울 9호선 전체의 노선·역·방향·열차종류·요일별 평균 혼잡도 패턴을 추정한다. 모델 대상인 열차 조사평균과 학습하지 않은 칸별 배분 시나리오를 구분한다. 지하철 차량 내부 센서, 칸별 재차인원 정답, 실제 환승 통로별 시간대 인원은 확보하지 못했다.

공식 원본:

- [서울교통공사 혼잡도 OA-12928](https://data.seoul.go.kr/dataList/OA-12928/F/1/datasetView.do): 1~8호선 9개 조사시점. 현재 페이지 이용허락 표시는 공공누리 3유형(출처표시·변경금지). 원본 수치와 추론값을 구분하고 원본 파일을 압축 보존한다. 데이터에 프로젝트 코드의 라이선스가 자동 적용되는 것은 아니다.
- [서울시 9호선 혼잡도 OA-22197](https://data.seoul.go.kr/dataList/OA-22197/F/1/datasetView.do): 2024·2025·2026년, 일반/급행·상하선·평일/휴일. 6량 922명 기준 100%라는 원본 설명을 따른다. 개별 칸의 정원을 따로 검증하지 않아 인원수로 환산하지 않는다. 2026년을 2026-12-31 관측이라고 가정하지 않고 연도 키 `2026`으로 보존한다.
- [환승 위치 OA-22521](https://data.seoul.go.kr/dataList/OA-22521/F/1/datasetView.do), [에스컬레이터 OA-22486](https://data.seoul.go.kr/dataList/OA-22486/F/1/datasetView.do), [9호선 시설 OA-22443](https://data.seoul.go.kr/dataList/OA-22443/L/1/datasetView.do).
- [역주소·전화번호 OA-12035](https://data.seoul.go.kr/dataList/OA-12035/F/1/datasetView.do), [역사마스터 좌표 OA-21232](https://data.seoul.go.kr/dataList/OA-21232/S/1/datasetView.do), [역간거리 OA-12034](https://data.seoul.go.kr/dataList/OA-12034/F/1/datasetView.do).
- [시간대별 승하차 OA-12921](https://data.seoul.go.kr/dataList/OA-12921/F/1/datasetView.do): 2023~2025 원문 시간대 열을 SQLite raw_records에 보존. 현재 칸별 모델의 입력은 아님.

## DB와 데이터 품질

원본 혼잡도 610,209개에 0·결측도 보존한다. 학습에서는 미운행 또는 미관측 여부가 모호한 0·결측을 제외하고, 해당 키의 과거 양수 이력을 사용한다. 유효 이력이 전혀 없으면 예측을 거부한다. 최신값이 없어 과거값을 쓸 때는 응답에 경고와 해당 관측시점을 표시한다.

315는 물리적 환승역 중복을 제거한 역 수가 아니라 호선별 역 레코드 수다. 2호선 까치산의 별도 운영코드도 포함된다. 289개 주소·314개 좌표가 연결되며 미확보 필드는 null이다. 부역명과 알려진 개명(당고개→불암산, 뚝섬유원지→자양)을 정규화하고 호선을 함께 비교한다. 다른 노선의 역 좌표·주소를 임의로 대입하지 않는다.

정제 관측과 함께 원본 파일 gzip 바이트·출처·SHA-256을 source_files에 저장한다. 승하차 원문은 날짜·역 키로 인덱스한 원래 행 JSON으로 저장해 시간대 집계구간(06시 이전/24시 이후 포함)을 훼손하지 않는다. 승하차 원본은 597,970행이며 혼잡도와 시간 단위가 다르다.

## 연결 관계와 차량 수

노선도 연결 관계를 명시적으로 정의하며 역 코드 숫자만 정렬해 연결하지 않는다. 특수 코드는 원본 관측 테이블에 남기고 출발 구간별 profile_station으로 매핑한다.

- 1호선 동대문→동묘앞→신설동, 8호선 복정→남위례→산성 순서를 반영.
- 2호선 본선 내/외선 10량, 성수지선 4량(성수 출발 조사코드 9002), 신정지선 6량(신도림 출발 9003). 별도 성수E 9001은 원본 DB에 보존하지만 독립 구간 예측에는 사용하지 않는다.
- 5호선 강동→길동은 2549, 강동→둔촌동은 9005 조사코드. 상선 합류는 원본 공통 키.
- 6호선 응암→역촌→불광→독바위→연신내→구산→응암은 하선 단방향. 순환 진입은 9006, 응암→새절은 2611. 역방향 순환 경로를 생성하지 않는다.
- 5~7호선 8량, 8호선 6량. [서울시 편성 설명](https://mediahub.seoul.go.kr/archives/809847), [서울교통공사 약냉방칸 자료](https://data.seoul.go.kr/dataList/OA-22530/L/1/datasetView.do).
- 9호선 6량, 일반 정차역 38개·급행 정차역 16개를 실제 시트에서 읽었다. 개화→김포공항 방향이 상선이며 [9호선 운영사 자료](https://www.metro9.co.kr/webzine/1710/sub04_01.html)와 대조했다. 급행의 플랫폼 위치는 다음 일반 인접역 방면으로 연결한다.

편성 수는 모델 설정이며 실시간 운행 열차의 편성을 확인한 값은 아니다. 임시 편성·운행 변경은 반영하지 못한다.

## 학습된 모델과 요청 시 추론

각 `line|station|direction|service|daytype|time` 키에 대해 조사시점 순으로 지수평활한다.

`m_t = alpha*y_t + (1-alpha)*m_(t-1)`

첫 양수 관측을 초기화값으로 사용한다. alpha 후보 1.0, 0.75, 0.5, 0.25, 0.1을 노선별 검증시점 MAE로 선택한다. 동일 성능이면 단순한 최신값(alpha=1)을 우선한다. 9호선은 학습시점이 하나이므로 alpha 후보가 같은 결과를 내며 계수 선택의 통계적 증거가 부족하다.

1~8호선은 2026-03 검증, 2026-06 테스트. 9호선은 2025 검증, 2026 테스트. 최종 성능 계산 후 전체 이력으로 서빙 artifact를 다시 학습한다. 최신 관측 기준선과의 비교 수치는 artifacts/metrics.json에 공개한다. 실제 데이터 공개 지연까지 재현한 운영 백테스트는 아니다.

요청 시 SQL에서 예전 예측 결과를 조회하지 않는다. artifact의 학습된 시간 패턴을 요청 시각으로 평가한다. 현재 30분 기준점과 다음 기준점의 선형보간으로 분·초에 따른 값을 계산한다. 다음 기준점이 없으면 현재 패턴을 유지한다. 이 보간은 기준점 사이의 추가 실측값을 의미하지 않으며 분 단위 정확도는 평가하지 않았다. 결과를 생성한 후에만 predictions에 저장한다.

## 칸별 배분: 학습하지 않은 가정

다른 노선에서 환승한 뒤 가까운 승차 호차 집합 T, 해당 방면의 에스컬레이터 접근 호차 집합 A를 사용한다. 중복 시설·동일 호차는 제거한다. 모든 호차/모든 문, 방향 모호, 출입구 번호만 있는 행은 특정 칸에 배정하지 않는다. 위치 수나 경로 수를 승객 수로 취급하지 않는다.

각 비어 있지 않은 집합 G에서 칸 c의 근접도는 `mean(exp(-0.5*(c-k)^2), k in G)`. T/A가 둘 다 있으면 동일 가중 평균한다. 이는 호차 번호 차이에 기반한 근접도이며 미터 단위 거리가 아니다.

`factor_c = (1-s) + s*proximity_c/mean(proximity)`

`car_estimate_c = predicted_train_mean*factor_c`

s 기본 0.2, 허용 0~0.3은 연구 가정이다. 칸별 정답으로 학습하지 않았다. 위치가 없으면 factor=1. 동일 정원의 편성 내 칸을 가정해 평균을 보존하지만, 실제 차량별 정원 차이는 미반영한다. 민감도 범위는 s=0과 0.3의 결과 범위이며 확률적 신뢰구간이 아니다. 많이 내리는 칸은 출발 후 혼잡도가 낮아질 수도 있어 하차 위치를 단순 양의 혼잡 가중치로 더하지 않는다.

## 사용하지 않은 데이터와 실측 확보 후 계획

월별 환승유입인원은 환승통로 인원이 아닌 타 호선에서 출발한 사람의 최종 하차량이므로 배분 입력에서 제외했다. [서울시 정의](https://data.seoul.go.kr/bsp/wgs/dataView/data300View/643.do)

행정동 생활인구·역 승하차량을 칸별 재차인원으로 바꾸는 계수는 정답 없이 정당하게 학습할 수 없어 이번 추정기에 넣지 않았다. 원본 승하차는 DB에 보존하여 이후 감독학습·분석에 사용할 수 있다. 실시간 승객·사고·행사·지연 정보에 반응하지 않는다.

칸별 실제 관측(관측일시·열차·역·방향·호차·정원·재차인원·도착 전/출발 후 정의)을 확보하면 기준모델/위치 추가/실제 환승 수요 추가를 같은 시간 분리 표본으로 비교한다. 같은 열차의 칸을 다른 데이터 분할로 흩어 놓지 않는다. 실측 평가 전에는 `car_accuracy=null`, `prediction_kind=unvalidated_car_scenario`를 유지한다.


## 전체 여정 경로 예측

노선별 역을 노드, 일반/급행 구간과 공식 자료로 확인한 환승 연결을 간선으로 한 그래프에서 Dijkstra 탐색을 수행한다. 출발·도착 노선 미지정이면 해당 역의 모든 지원 노선 노드가 후보가 된다. 노선은 같아도 지선/본선 편성, 일반/급행, 운행방향 교체는 열차 변경으로 처리한다. 6호선 응암순환의 조사 방향 명칭 전환은 같은 열차의 연속 운행으로 처리한다.

전체 경로의 모든 구간에 같은 시각을 넣지 않고 이동·환승 가정으로 시각을 누적해 각각 추론한다. 한 열차에 머무는 leg 단위로 칸별 탑승시간 가중 평균과 최대를 제공한다. 환승 전후 칸을 같은 칸으로 합치지 않는다. 전체 평균은 예측 가능한 탑승 구간만 포함하며 보행·대기시간은 제외한다. 일부 구간의 타깃 패턴이 없거나 지원 운행시간 밖이면 부분 결과로 표시한다.

현재 역간 실시간 시간표·열차 운행 식별자가 없으므로 일반 구간 2분, 급행은 건너뛴 일반 역 수×1.3분(최소 2분), 환승은 방향별 공개 보행시간의 평균+3분 대기라는 가정이다. 이 값은 도착시각의 검증된 예측이나 실제 최단시간 보장이 아니다. 같은 노선에서 열차를 바꿀 때의 별도 보행시간은 모델링하지 않는다. 경로는 혼잡도 최적화가 아닌 추정 소요시간/환승 횟수 최적화다.
