# 서울 지하철 혼잡도 서비스 — Phase 2

**역 상세정보·시간대별 원본 관측값은 SQLite에 저장하고, 혼잡도는 FastAPI 요청 시 예측모델로 추론합니다.** 서울교통공사 1~8호선 운영구간과 서울 9호선 전체를 지원합니다. 2호선 지선, 5호선 분기, 6호선 단방향 순환, 9호선 일반/급행을 구분합니다.

칸별 실측 정답은 아직 없습니다. 열차 평균은 공개 조사자료로 학습·평가하고, 칸별 값은 환승·접근 위치에 따른 **검증되지 않은 배분 시나리오**로 반환합니다. 실시간은 요청 시 계산을 뜻하며 실시간 센서 관측, 실제 도착 열차의 실측 혼잡도를 뜻하지 않습니다.

| 2호선 (본선·성수지선·신정지선) | 51 | 102 |
| 3호선 (지축~오금) | 34 | 66 |
| 4호선 (불암산~남태령) | 26 | 50 |
| 5호선 (방화~하남검단산/마천) | 56 | 110 |
| 6호선 (응암순환·응암~신내) | 39 | 72 |
| 7호선 (장암~온수) | 42 | 82 |
| 8호선 (암사역사공원~모란) | 19 | 36 |

환승역은 호선마다 별도 레코드입니다. 1·3·4호선의 코레일 구간, 7호선 인천 운영구간, 8호선 별내선의 다른 운영기관 구간은 현재 공식 혼잡도 파일 범위 밖입니다. 수도권 모든 운영기관·노선을 지원한다는 의미는 아닙니다. 일반은 인접역, 급행은 다음 급행 정차역 구간을 입력합니다. 전체 여정은 아래 `/v1/journeys/predict`에서 환승을 포함해 탐색합니다.

## Docker Compose로 로컬 실행

```sh
./scripts/compose.sh up -d --build --wait --wait-timeout 240
```

화면은 http://localhost:8080, API 문서는 http://localhost:8080/docs 입니다. Nginx·Next.js·FastAPI와 SQLite 영속 볼륨을 함께 실행합니다. [상세 실행·원본 적재·검증·CI/CD 연결 안내](docs/local-compose.md)를 참고하세요.

## 실행 및 원본 DB 적재

Python 3.11 이상, 저장소 루트에서:

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
python -m scripts.bootstrap --download
python -m scripts.train
python -m pytest -q
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

`bootstrap --download`는 포함된 관측 데이터로 DB를 만들고, 없는 공식 원본을 내려받아 해시 검증 후 DB에 적재합니다. 기존 로컬 수집 파일이 있으면 재사용합니다. 공식 원본이 갱신되어 해시가 달라지면 중단하므로 새 버전을 검토해야 합니다. 원본 다운로드 없이 모델·API만 시험할 때는 `--skip-originals`를 사용합니다. 이 모드에서는 승하차 원본 조회 데이터가 없으며, 610,209개의 혼잡도 관측값 및 역/구간 정보는 적재됩니다.

기본 DB는 `var/subway.sqlite3`. API의 `SQLITE_PATH` 환경변수로 변경할 수 있습니다. CLI는 `--db /path/to/subway.sqlite3`로 동일 경로를 지정하세요. 동일 시드 버전의 재실행은 관측값을 중복 적재하지 않으며 예측 이력을 보존합니다. DB는 Git에 올리지 않습니다.

실제 적재 검증 결과:

- 역 정보 315건: 주소·전화번호 289건, 좌표 314건. 미확보 필드는 null.
- 방향별 구간 640건, 열차 혼잡도 원본 수치 610,209건(0·결측 포함).
- 2023~2025년 시간대별 승하차 원본 597,970행. 원래 시간대 열과 행 번호를 JSON으로 보존.
- 환승·시설 위치 레코드 2,774행, 공식 원본 파일 압축본·출처·SHA-256 저장.
- DB는 약 0.7GB. RAM으로 전체 DB를 읽지 않으며 학습은 노선별, 원본 API는 페이지 단위로 조회.

## 전체 구간 예측 — 기본 사용 방식

`건대 → 고속터미널`처럼 출발역·도착역을 입력합니다. 노선을 생략하면 해당 역의 모든 지원 노선에서 경로를 찾습니다. 시간 생략 시 한국 현재시각입니다.

```sh
curl -X POST http://127.0.0.1:8000/v1/journeys/predict \
  -H 'Content-Type: application/json' \
  -d '{"from_station":"건대","to_station":"고속터미널","at":"08:15"}'
```

현재 모델은 이 예에서 7호선 직통 7개 구간을 선택합니다. 08:15 출발이면 각 구간의 예측시각을 08:15, 08:17, …로 이동시키며, 가정상 도착은 08:29입니다. **14분은 실제 시간표에서 확인한 소요시간이 아니라 구간당 2분이라는 가정의 결과**입니다.

- `from_line`, `to_line`: 선택적으로 출발·도착 승강장의 노선을 제한.
- `strategy`: `estimated_fastest`(가정한 이동시간 기준) 또는 `fewest_transfers`(환승 횟수 우선).
- `allow_express`: 9호선 급행 포함 여부, 기본 true.
- `legs`: 같은 열차에 머무는 구간별 칸의 평균·최대 혼잡도 시나리오. 환승 후 칸 번호는 다른 열차의 칸입니다.
- `steps`: 각 탑승 구간의 예상 진입시각·칸별 예측, 환승 보행·대기 단계.
- `status`: `complete`, `partial`, `unavailable`. 운행 종료 등으로 일부 예측이 없으면 해당 구간의 이유와 집계 범위를 표시.
- `estimated_minutes`, `estimated_arrival_at`: 시간표 미연동 추정. 일반 구간당 2분, 급행은 통과 역 수로 추정, 환승은 공식 방향별 보행시간 평균(없으면 5분)+대기 3분. 동일 호선의 지선/본선·일반/급행·운행방향 교체도 별도 열차로 나누고 대기 3분을 가정합니다.

역 약칭 `건대`, `고터`를 지원합니다. 경로 탐색은 이동시간 또는 환승 횟수를 기준으로 하며 혼잡도가 가장 낮은 경로를 최적화하는 알고리즘은 아닙니다. 출발역에서 첫 열차를 기다리는 시간은 포함하지 않습니다.

## 단일 구간 예측 API — 상세 조회용

Swagger: `http://127.0.0.1:8000/docs`

```sh
curl -X POST http://127.0.0.1:8000/v1/predict \
  -H 'Content-Type: application/json' \
  -d '{"line":9,"service":"급행","from_station":"김포공항","to_station":"마곡나루","at":"08:15"}'
```

- `line`: 1~9. 기존 2호선 API 호환용 기본값 2. 프론트에서는 명시적으로 보내세요.
- `service`: `일반` 또는 `급행`. 급행은 9호선만 지원.
- `at` 생략: 한국 현재시각. `08:15`: 한국 오늘 날짜. ISO 8601 datetime도 지원. 시간대 없는 값은 한국 시각.
- `scenario_strength`: 0~0.3, 기본 0.2. 위치 집중도 가정으로 학습된 계수가 아님.
- `00:00~00:59`는 전날 운행일 `24:00/24:30`. 01:00~05:29는 지원 밖. 해당 요일·시간의 관측 패턴이 없으면 422.
- 공휴일은 1~8호선 일요일, 9호선 휴일 패턴으로 대체. 9호선 휴일은 토·일요일 공통이며 자정 이후 자료가 없음.
- 현 모델 자료 기준일 이하 조회는 거부합니다. 1~8호선 2026-06-30, 9호선 2026-09-09(2026년 파일 공개시점). 과거 검증은 별도 시간 분리 평가를 확인하세요.

응답의 `train_mean_congestion_pct`는 조사평균 패턴을 시간에 따라 보간한 요청 시점 추론값입니다. `cars`는 편성에 따라 4·6·8·10개 항목이며, 칸별 평균이 열차 평균과 일치하도록 배분합니다. `scenario_range_pct`는 배분 가정 변화의 민감도 범위로 신뢰구간이 아닙니다. `prediction_kind`, `evidence`, `warnings`를 프론트에서도 표시해야 합니다. 결과 예시는 [example-response.json](docs/example-response.json)에 있습니다.

## DB 조회 API

| 경로 | 내용 |
|---|---|
| GET `/health` | 로드된 모델 상태 |
| GET `/v1/segments?line=9` | DB에서 로드한 지원 구간 목록 |
| GET `/v1/stations?line=9` | 노선별 역 목록 |
| GET `/v1/stations/2:226` | 사당 2호선 주소·전화번호·좌표·운영기관 |
| GET `/v1/stations/2:226/observations?limit=100&offset=0` | 원본 혼잡도 관측값 페이지 조회, 특수 운행코드 포함 |
| GET `/v1/stations/2:226/ridership?service_date=2025-01-01` | 해당 일자의 원문 시간대별 승하차 행 |
| GET `/v1/model` | 호선별 평가 결과와 공식 출처 |
| POST `/v1/journeys/predict` | 환승 포함 전체 경로·구간별 시각·칸별 집계 |
| POST `/v1/predict` | 요청 시 모델 추론 및 SQLite 결과 저장 |

DB의 `stations`, `segments`, `observations`, `raw_records`, `source_files`는 근거 데이터이며 `predictions`는 요청별 결과 이력입니다. 모델은 raw 관측값을 곧바로 칸별 정답으로 반환하거나 과거 예측 결과를 조회해서 응답하지 않습니다. 예측 이력은 최근 1,000건을 유지합니다. SQLite WAL 및 요청별 연결 종료를 적용했습니다.

## 학습과 평가

`scripts/train.py`가 DB의 노선별 조사 이력을 읽어 직접 구현한 지수평활 계수를 선택합니다. 1~8호선: 7개 과거 조사로 학습→2026-03 검증→2026-06 테스트. 9호선: 2024 학습→2025 검증→2026 테스트. 자료 단위가 다른 9호선은 분리 평가합니다. 9호선은 최초 학습시점이 하나여서 평활 계수 선택을 충분히 검증할 수 없는 제약이 있습니다.

테스트 MAE(%p): 1호선 1.708, 2호선 2.957, 3호선 1.463, 4호선 1.918, 5호선 2.033, 6호선 1.680, 7호선 2.215, 8호선 2.272, 9호선 4.016. 이는 **조사시점의 열차 평균값**에 대한 값이며 칸별 정확도가 아닙니다. 시간 보간은 평가된 30분 기준점을 연결하는 가정으로, 분 단위 실측 검증을 하지 않았습니다. 상세 지표·기준선은 `artifacts/metrics.json`, 한계와 수식은 [모델 카드](docs/model-card.md)에 있습니다.
