# 지하철 칸별 혼잡도 추정 — Phase 1

2호선 본선의 **인접한 두 역 사이 구간**과 시간을 입력하면 10개 칸의 혼잡도 추정 시나리오를 반환하는 FastAPI 서비스입니다. 시간 생략 시 한국 현재 시각을 사용합니다. 43개 역·양방향 86개 구간을 지원하며 지선·급행·환승 경로 검색은 지원하지 않습니다.

**칸별 실측 정답은 없습니다.** 공개 조사자료로 학습·평가한 열차 평균 혼잡도와, 환승/접근 위치에 따른 가정 기반 칸별 배분을 구분합니다. 화면이나 발표에서 결과를 실시간 실측 또는 검증된 칸별 예측 정확도로 설명하지 마세요. API의 `prediction_kind`, `warnings`, `evidence`에도 이 구분을 포함합니다.

## 실행

Python 3.11 이상, 저장소 루트에서:

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
python -m scripts.train
python -m pytest -q
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

학습용 소규모 파생 데이터와 학습 결과를 포함하므로 원본 1GB를 다시 받지 않아도 실행·재학습할 수 있습니다. `http://127.0.0.1:8000/docs`에서 요청을 시험할 수 있습니다. 별도 터미널에서:

```sh
curl -X POST http://127.0.0.1:8000/v1/predict \
  -H 'Content-Type: application/json' \
  -d '{"from_station":"사당","to_station":"방배","at":"08:15"}'
```

- `at` 생략: 현재 한국 시각.
- `at: "08:15"`: 한국 오늘 날짜 08:15.
- `at: "2026-09-21T08:15:00+09:00"`: 특정 날짜·시각. 시간대 없는 datetime은 한국 시각.
- `scenario_strength`: 0~0.3, 기본 0.2. 칸별 위치 집중도를 가정하는 계수이며 학습된 값이 아닙니다. 0은 균등 배분.
- `01:00~05:29`, 지원하지 않는 구간, 유효 조사값 없는 구간·시간은 HTTP 422.
- `00:00~00:59`는 전날 운행일의 `24:00/24:30` 구간. 공휴일은 일요일 패턴으로 대체하며 경고를 반환합니다.
- 현재 artifact의 학습 기준일인 2026-06-30 이전/당일 운행일 조회는 거부합니다. 과거 성능 검증은 별도의 시간 분리 평가로 수행합니다.

## API

| 경로 | 역할 |
|---|---|
| GET `/health` | 로드된 모델 상태 |
| GET `/v1/segments` | 지원하는 방향별 인접 구간 목록 |
| GET `/v1/model` | 모델 평가 결과와 데이터 출처 |
| POST `/v1/predict` | 열차 평균 추정 및 칸별 시나리오 |

주요 응답 필드:

- `train_mean_congestion_pct`: 출발역·방향·30분 조사평균의 예측값. 개별 열차의 진입 전/출발 후 순간값이 아닙니다.
- `cars[].estimated_congestion_pct`: 위치 가정으로 배분한 칸별 혼잡률. 100%를 넘을 수 있습니다.
- `cars[].scenario_range_pct`: 배분 강도를 0~0.3으로 바꿨을 때의 민감도 범위. 통계적 신뢰구간이 아닙니다.
- `location_features`: 해당 방면과 일치하는 환승 승차/에스컬레이터 인접 호차.
- `evidence`: 학습 기준일, 해당 패턴 마지막 관측시점, 조사 건수, 칸별 실측 정답 건수(0).

예측 결과는 SQLite `var/subway.sqlite3`에 저장됩니다. `SQLITE_PATH`로 변경할 수 있습니다. WAL과 요청별 연결을 사용하고 최근 10,000개 결과만 보관합니다. DB와 비밀정보는 Git에서 제외합니다. 공개 이력 조회 API는 없습니다.

## 모델 및 검증 결과

직접 구현한 지수평활 모델의 계수를 시간 분리 검증으로 선택합니다. 결과적으로 계수 1.0, 즉 가장 최근 유효 조사값을 사용하는 기준선이 선택됐습니다. 신경망이나 외부 예측 API를 호출하지 않습니다.

- 입력 조사값 90,558개; 유효 양수 86,897개; 0/결측 3,661개는 미운행 여부가 불명확해 제외.
- 2024-03~2025-11 조사 7개로 후보 학습 → 2026-03 조사로 계수 선택 → 2026-06 조사로 최종 평가.
- 최종 평가 9,605개: 열차 평균 MAE **3.2165%p**, RMSE **4.8384%p**.
- 기준선보다 성능이 개선됐다는 주장은 하지 않습니다. 선택된 모델 자체가 최신 조사값 기준선입니다.
- 칸별 MAE는 **산출 불가**. 같은 조사기간 내 반복 패턴을 일별 독립 관측으로 세지 않습니다.
- 서빙 artifact는 평가 완료 후 9개 조사시점 전체로 재학습했습니다. 실제 사용시점별 파일 공개 지연을 재현한 운영 백테스트는 아닙니다.

칸별 배분은 동일 정원의 10량 편성을 가정하고 평균을 보존합니다. 86개 방향 중 51개에는 방향이 일치하는 위치 피처가 있으며, 나머지는 균등 배분합니다. 위치가 있다는 이유만으로 해당 칸이 실제 가장 혼잡하다고 판단할 수 없습니다. 자세한 식과 제외한 데이터는 [모델 카드](docs/model-card.md)를 확인하세요.

## 데이터와 재현

- `datasets/congestion.csv.gz`: 2호선 본선 조사값 소규모 파생본.
- `datasets/stations.json`, `locations.json`: 본선 역과 방향별 접근 위치.
- `datasets/provenance.json`: 서울교통공사 출처·원본 파일 SHA-256·파생본 SHA-256.
- `scripts/prepare.py`: 기존 로컬 조사 산출물에서 소규모 학습 입력을 생성. 이 단계만 pandas 필요.
- `scripts/train.py`: 표준 라이브러리만으로 학습·평가. 결과 `artifacts/model.json`, `metrics.json`.
- `app/`: 추정 알고리즘과 FastAPI/SQLite 서비스.
- `tests/`: 전체 86구간 평균 보존, 방향·시간·유효성 검사, 결측 처리, 저장·동시 요청 검사.

공식 제공기관: 서울교통공사. 출처:
[혼잡도 OA-12928](https://data.seoul.go.kr/dataList/OA-12928/F/1/datasetView.do),
[환승 위치 OA-22521](https://data.seoul.go.kr/dataList/OA-22521/F/1/datasetView.do),
[에스컬레이터 OA-22486](https://data.seoul.go.kr/dataList/OA-22486/F/1/datasetView.do).
원본이 갱신되면 새 버전으로 검증 후 배포해야 합니다. 모든 원본·안내도 이미지는 저장소에 포함하지 않습니다.

## 이후 Phase

최종 목표는 최소 규모 EC2 한 대에 FastAPI, SQLite, Next.js, Tailwind CSS를 배치하고 IP로 접근하는 서비스입니다. 프론트 테마는 연성대학교 공식 로고 색상을 확인한 뒤 적용합니다. 이번 Phase에는 프론트엔드나 AWS 리소스를 만들지 않았습니다. EC2 사양은 Next.js 빌드·런타임 메모리까지 실측한 뒤 선정합니다.

작업 Phase 종료 시 테스트 및 변경 검토 후 이 저장소에 commit/push합니다. 비밀정보·DB·대용량 원본은 커밋하지 않습니다.
